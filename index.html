Differences in Language-Learning Difficulties by First Language¶

Alan Golik

CMPS 3160, Professor Saad Hassan

Website

Motivation and Data Source¶

Adult language learners do not usually struggle equally with every aspect of the language they are learning; they tend to have more trouble with specific areas. A learner of English, for example, might have particular difficulty with articles, or a learner of Spanish with the subjunctive or grammatical gender. This varies from person to person, of course, as well as by native language, but there may also be broader patterns in the difficulties people have with language learning which have more global implications.

To examine these topics, I will be using two Duolingo datasets I obtained from Kaggle, at https://www.kaggle.com/datasets/aravinii/duolingo-spaced-repetition-data and https://www.kaggle.com/datasets/mesumraza/duolingo-global-language-popularity-data, both obtained originally from Duolingo itself. The first contains around thirteen million "traces" from language learners; each row is a word that one user encountered in one lesson, with data such as the user's UI language and language of study, the word's grammatical features, whether the user got it correct, and many others. Each word also comes with grammatical information, which makes it perfect; I can study the proportions of correct answers on words with certain grammatical features, which are highly language-specific. This is exactly what I want to examine! The second contains information about the most and second-most popular languages on Duolingo in each country from 2020 to 2024. This, combined with the previous dataset, can give me plenty of information on the effects of a language's difficulty for users on its global popularity.

Duolingo is a popular language-learning app that presents an opportunity to study a language casually with a much lower time commitment than traditional approaches (~30 minutes per day or less). The fact that lessons (necessarily, since accuracy is judged by a computer program) focus on translation rather than natural production of language may affect the difficulties students have, and this should be kept in mind when interpreting the data and this project's analysis of it.

This project aims to answer the following question: Can we predict the language someone is learning by using the proportions of times they get different parts of speech correct?

Let's begin with a quick breakdown of the variables:

  • learning_language — The language the user is learning.

  • ui_language — The language to which the user's interface is set, likely their native language.

  • lexeme_string — The "lexeme", or word, that the user encountered. The string begins with the particular form of the word found in the lesson (e.g. "ran"), then the "lemma" (basic) form of the word (e.g. "run"), and various grammatical information as brief tags enclosed in angle brackets. The part of speech is given first. A noun is marked <n>, a lexical verb (one that carries meaning) is marked <vblex>, a determiner (such as an article) is marked <det>, etc. Nouns, adjectives and determiners come with information about gender (masculine, feminine or neuter), number (singular or plural) and case (nominative, accusative, dative or genitive, each marking a different grammatical role in the sentence) when the language has these. (All five languages other than English have grammatical gender on nouns, adjectives and determiners, only German marks case, and all six languages mark number on nouns, with the five other than English also marking it on determiners and adjectives.) Verbs have information about tense, voice, mood, person and number. In general, all words have tags for any grammatical feature that might be relevant.

  • session_seen — The number of times the given lexeme/form of the word appeared in the given lesson/practice

  • session_correct — The number of times the user got the word correct

  • history_seen and history_correct — The same as the two above, but across all previous lessons/practices rather than the current one

  • p_recall — The proportion of times that the word was correctly recalled in this session: equal to session_correct divided by session_seen

  • user_id — An anonymized ID number for the user

  • timestamp — The UNIX timestamp of the lesson

  • delta — The number of seconds since the previous lesson where this word came up

  • lexeme_id — The system ID for the given lexeme

Each row already corresponds to one observation, with each variable comprising a column and the whole table comprising an observational unit. Therefore, the data appears to already be tidy (with the exception that multiple dtypes are present in the same dataset, but this seems unavoidable), and no melting is necessary. However, there is still some processing to do. The timestamp and delta columns, for instance, are not remotely related to our purposes with the data. Also, since the lexeme_string column also uniquely identifies the word/lexeme under observation, the lexeme_id column is redundant (and less easily interpretable). Also, we don't need the "session_seen", "session_correct" or "p_recall" variables if "history_seen" and "history_correct" are more comprehensive. Therefore, we can safely delete all of these.

Our users have their UIs set to English, Portuguese, Spanish, or Italian, and are learning those languages plus German and French. This is a small group of closely related languages — English and German are both Germanic, the other four are all Romance, all are Indo-European, and they have had plenty of contact with each other over many centuries. All of these languages share many grammatical features, so the difficulties learners have may not be as varied as we would like to see. Nonetheless, a study on these six still promises to be interesting.

We should note that the ui_language column contains the language to which the user has set their interface — the language from which they are learning their target language, which is stored in learning_language. For most users, this will likely be their native language or one they use regularly in everyday life, but some users may be challenging themselves to learn a target language from another target language, to improve their command of the UI language as well. This is a common enough practice that it may affect a large part of our dataset, and we should keep it in mind when analyzing and interpreting the data.

As we can see, this dataset has a pretty clear limitation: it only records users who speak or are learning English. I could predict whether an English-learner speaks Spanish, Portuguese or Italian based on the proportions of different types of English words they get right. However, I suspect these three languages are too similar grammatically for there to be any meaningful differences. As such, I will try to predict the language an English-speaker is learning (German, French, Spanish, Portuguese or Italian) based on their difficulties with different parts of speech. There is a slightly greater variety of languages here, and French and German especially are different enough from the rest that it should make a difference. Finally, let's take a look at the proportions of words of different parts of speech that users got right. The first thing to do is make sure the same word appearing more than once for the same user doesn't skew the results. Since history_seen and history_correct record the TOTAL number of times a user has seen a word or gotten it correct, if we find a duplicate word for a given user, we just need to keep the one with higher values of these variables — the more comprehensive one (this version of the word was encountered by the user later and therefore its history_seen and history_correct values are more recent).

In [12]:
# I group the dataframe by user ID and lexeme string (grouping the rows with the same word and user),
# take the maximum of their history_seen and history_correct values, and add these columns onto traces_df.
# Then, I use them to calculate the proprtion of correct answers overall for a given word, drop the four now-redundant columns,
# and drop the duplicate rows.

total_history = traces_df.groupby(by = ["user_id", "lexeme_string"])[["history_seen", "history_correct"]].agg(func = "max")
traces_df = traces_df.join(other = total_history, on = ["user_id", "lexeme_string"], lsuffix = "_old")
traces_df["prop_correct"] = traces_df["history_correct"]/traces_df["history_seen"]
traces_df.drop(columns = ["history_seen_old", "history_correct_old", "history_seen", "history_correct"], inplace = True)
traces_df.drop_duplicates(inplace = True)

Modeling¶

As I mentioned earlier, I'd like to predict the language someone is learning by using the proportions of times they get different parts of speech correct. To answer this, let's build a k-nearest-neighbors classification model. The independent variables (input to the distance function) will be the aggregate proportions of correct answers for different parts of speech for a given user (observation), and the dependent variable (output) would be the language that user is learning. Obviously, given our data, this model will assume the user's first language is English.

Let's import Scikit-Learn and built a k-nearest-neighbors classifier! Our data is all on the same scale (proportions from 0 to 1), so no need to rescale/normalize.

In [53]:
import sklearn

X = user_traces_df.drop(columns = "learning_language")
y = user_traces_df["learning_language"]

X_train, X_test, y_train, y_test = sklearn.model_selection.train_test_split(X, y, test_size=0.5)

KNC = sklearn.neighbors.KNeighborsClassifier(n_neighbors=100)
KNC.fit(X_train, y_train)

y_predict = KNC.predict(X_test)

sklearn.metrics.accuracy_score(y_test, y_predict)
Out[53]:
0.711504472176102

Given that we have around 100,000 entries, 100 seemed to be a reasonable number of neighbors. With this, we get an accuracy of around 0.712.

Conclusion¶

Overall, we see that proportions of correct answers on different parts of speech is not the best predictor of what language someone is learning, at least among the five closely-related European languages we studied. An avenue for further research/modeling might be looking at features like grammatical gender, case and tense directly, rather than simply parts of speech. This tells us that among these five languages, there are certainly some differences in difficulties among English-speakers between different parts of speech, but they aren't that great a predictor of what language a given English-speaker is learning.
